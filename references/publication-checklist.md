# TradingView Publication Checklist

Use this when the user wants publish-ready copy or a commercial or invite-only feel.

## Public or open-source publication checklist

- Be original and useful.
- Explain what the script does, not who the company is.
- Credit reused ideas when relevant, but do not rely on copied code.
- Use a clear, restrained title and chart.
- Prefer a private draft before public release.
- Review title and description carefully before publishing.

## Invite-only or vendor-oriented checklist

- Explain the underlying principles clearly enough for a reviewer or buyer to understand the value.
- Do not include pricing in the description.
- Do not solicit likes, comments, or follows.
- Do not make unrealistic claims or guarantees.
- If the script uses classic indicators or public-domain concepts, explain what is original about the implementation.
- If you show strategy results, document the exact properties used, including commission and slippage.
- Mention intended markets, timeframes, and limits.
- Put access-request instructions in the Author's instructions field, not in the description.
- Do not use private invite-only publication as a workaround for non-compliant content.

## Reuse and originality

- If code is derived from open-source TradingView scripts and will be republished, meaningful improvement plus attribution is required.
- For paid or invite-only reuse, permission is required.
- This skill should generate original code instead of copying.

## Description skeleton

1. What it is
2. Core logic
3. Input groups
4. Alerts and automation
5. Intended markets and timeframes
6. Backtest settings and assumptions for strategies
7. Limitations
8. Disclaimer

## Tone rules

- Be grounded, specific, and restrained.
- Avoid hype such as:
  - best ever
  - guaranteed
  - never loses
  - holy grail
  - secret institutional edge unless actually explained
  - AI or ML hype without real external AI
- Prefer phrases such as:
  - designed for
  - intended for
  - uses
  - approximates
  - works best when
  - limitations include

## Strategy-specific copy requirements

- Mention the signal logic.
- Mention the risk model and exits.
- Mention the commission and slippage assumptions used for shown results.
- Mention whether entries are confirmed-bar or intrabar.
- Mention whether the script is optimized for specific markets or sessions.
- Mention weak conditions or regimes.

## Charts and visuals

- Keep visuals informative, not splashy.
- Make it easy to see what the script adds to price or to a subpanel.
- Show the key output, not decorative text.

## Release notes

- Limit release notes to actual changes.
- Do not use release notes as marketing copy.

## Access instructions for invite-only scripts

- Tell users to contact privately or follow the allowed access path.
- Do not ask them to request access in public comments.
